Docker: шпаргалка с нуля

Для тех, кто раньше не трогал Docker. Читай по порядку и сразу повторяй команды: 1–7 — запускать готовые сервисы, 8 — собрать свой образ, 9 — описать сервисы файлом, в конце практика.

1. Что это и зачем

Нужно поднять сайт, базу данных, облако для файлов, мониторинг или запустить чужой проект с GitHub. Без Docker: ставить пакеты, подбирать версии, чинить конфликты, а на другом компьютере всё заново. С Docker: одна команда — через минуту работает, не понравилось — удалил без следов. Почти любая программа уже лежит готовой на hub.docker.com.

Хватит трёх слов:

  • Образ — программа, упакованная со всем, что ей нужно. Как установщик: скачал один раз, запускай сколько угодно.
  • Контейнер — запущенный образ, то есть работающая программа. Удалил контейнер — образ остался, можно запустить заново.
  • Том — папка с данными программы, лежит отдельно от контейнера. Как сохранения в игре: переустановил игру — сохранения на месте.
 Docker Hub --скачать--> ОБРАЗ --запустить--> КОНТЕЙНЕР --данные--> ТОМ

2. Установка

Linux-сервер:

curl -fsSL https://get.docker.com | sudo sh   # поставить Docker
sudo usermod -aG docker $USER                 # чтобы не писать sudo перед каждой командой

Выйди и зайди по SSH заново, потом проверь:

docker run hello-world    # написал "Hello from Docker!" — всё работает

Windows / macOS: скачай Docker Desktop с docker.com, установи и запусти. Команды те же — в PowerShell или Терминале.

3. Первый сервис за минуту

Поднимем Uptime Kuma — веб-мониторинг: следит, работают ли твои сайты и серверы, и присылает уведомление (Telegram, почта), когда что-то упало.

docker run -d --name kuma -p 3001:3001 -v kuma-data:/app/data --restart unless-stopped louislam/uptime-kuma:1

Открой http://IP-сервера:3001 (на своём компьютере — http://localhost:3001), заведи логин и добавь свой сайт. Разбор команды:

docker run                  # скачать образ (если ещё нет) и запустить контейнер
-d                          # работать в фоне, терминал свободен
--name kuma                 # имя контейнера, по нему им управлять
-p 3001:3001                # порт сервера 3001 -> порт 3001 в контейнере
-v kuma-data:/app/data      # данные программы хранить в томе kuma-data
--restart unless-stopped    # упал или сервер перезагрузился — запустить снова
louislam/uptime-kuma:1      # образ: автор/название:версия

 браузер: http://сервер:3001
        |
        |  -p 3001:3001  (порт сервера -> порт контейнера)
        v
 [ контейнер kuma, порт 3001 ]
        |
        |  -v kuma-data:/app/data  (папка в контейнере -> том)
        v
 [ том kuma-data на диске сервера ]  <- переживёт удаление контейнера

4. Управление контейнерами

docker ps                 # какие контейнеры работают
docker ps -a              # все, включая остановленные и упавшие
docker logs kuma          # что пишет программа — ошибки ищи тут
docker logs -f kuma       # лог вживую (выход: Ctrl+C)
docker stop kuma          # остановить
docker start kuma         # запустить снова
docker restart kuma       # перезапустить
docker rm -f kuma         # удалить контейнер (том с данными останется)
docker exec -it kuma sh   # зайти внутрь, как по SSH (выход: exit)
docker inspect kuma       # все настройки контейнера: IP, тома, переменные
docker stats              # кто сколько ест CPU и памяти (выход: Ctrl+C)
docker images             # скачанные образы
docker run --rm -it alpine sh   # разовый Linux «потрогать»; после exit удалится сам

Как читать docker ps (колонки сокращены):

IMAGE                    STATUS         PORTS                    NAMES
louislam/uptime-kuma:1   Up 5 minutes   0.0.0.0:3001->3001/tcp   kuma
  • Up — работает. Exited (1) — упал, смотри docker logs kuma. Restarting — падает и поднимается по кругу, тоже смотри логи.
  • 0.0.0.0:3001->3001 — порт 3001 сервера открыт для всех и ведёт в контейнер.

5. Данные и обновление

Контейнер одноразовый: удалил — всё, что программа записала внутрь, пропало. Поэтому папку с данными всегда выносят наружу флагом -v:

-v kuma-data:/app/data                     # том: Docker хранит данные сам
-v ./site:/usr/share/nginx/html:ro         # твоя папка — внутрь контейнера
-v ./nginx.conf:/etc/nginx/nginx.conf:ro   # или один файл: так подкладывают конфиги

Слева — что с сервера, справа — куда внутри контейнера (это смотри на странице образа на Docker Hub). :ro — контейнер может только читать. Правило: данные программы (базы, загрузки) — в том, свои файлы и конфиги — папкой или файлом.

Обновление сервиса на новую версию — данные в томе не пострадают:

docker pull louislam/uptime-kuma:1   # скачать свежий образ
docker rm -f kuma                    # удалить старый контейнер
docker run -d --name kuma ...        # та же команда, что при первом запуске

Чтобы не держать длинные команды в голове, постоянные сервисы описывают файлом — см. Compose.

docker volume ls             # список томов
docker volume rm kuma-data   # ⚠ удалить том = удалить данные навсегда

6. Порты и сеть

-p 8080:80              # слева порт СЕРВЕРА, справа порт КОНТЕЙНЕРА
-p 127.0.0.1:8080:80    # открыть только для самого сервера, не для сети
-p 53:53/udp            # UDP-порт: допиши /udp
  • Без -p снаружи до программы в контейнере не достучаться.
  • Слева — любой свободный порт: два nginx можно запустить как -p 8081:80 и -p 8082:80. Порт справа смотри на странице образа.
  • ⚠ Docker открывает порты в обход ufw/firewalld. Не хочешь светить сервис в сеть — пиши 127.0.0.1: или не публикуй порт.
  • localhost внутри контейнера — это сам контейнер, а не сервер.

Контейнеры общаются между собой через свою сеть — по именам, без IP. Пример: база PostgreSQL + веб-админка к ней.

docker network create mynet
docker run -d --name db --network mynet -e POSTGRES_PASSWORD=secret postgres:16
docker run -d --name adminer --network mynet -p 8080:8080 adminer:4
# в Adminer (http://сервер:8080): система PostgreSQL, сервер db, логин postgres, пароль secret
docker rm -f db adminer      # убрать за собой
  • -e ИМЯ=значение — настройка программы через переменную (тут пароль базы).
  • Без своей сети (--network) имена не работают. Compose создаёт такую сеть сам.

Частный случай: сетевые сервисы

docker run -d --name iperf -p 5201:5201 -p 5201:5201/udp networkstatic/iperf3 -s   # сервер замера скорости
docker run --rm -it nicolaka/netshoot     # набор утилит: ping, mtr, dig, tcpdump, nmap, iperf3
  • --network host — контейнер работает прямо на сетевых интерфейсах сервера: без -p и без NAT. Нужно для DHCP, multicast и программ с кучей портов. Только Linux.
  • macvlan — у контейнера свой MAC и IP в локальной сети, как у отдельного компьютера: docker network create -d macvlan --subnet 192.168.1.0/24 --gateway 192.168.1.1 -o parent=eth0 lan, затем docker run --network lan --ip 192.168.1.50 .... Сам сервер до такого контейнера напрямую не достучится — так устроен macvlan.
  • Под капотом: -p — это DNAT на сервере, выход контейнеров наружу — PAT (masquerade) за IP сервера, контейнеры сидят в bridge-сетях 172.17.0.0/16 и дальше. Правила: sudo iptables -t nat -nL DOCKER.

7. Как запустить любой сервис

  1. Найди образ на hub.docker.com. Бери с пометкой Docker Official Image или Verified Publisher, либо тот, на который ссылается документация самой программы.
  2. На странице образа найди три вещи: порт веб-интерфейса, папку данных, переменные (пароль админа и т.п.).
  3. Собери команду по шаблону из раздела 3.
  4. Большие программы (Nextcloud, WordPress, Zabbix) обычно дают в документации готовый compose.yaml — бери его и запускай по разделу 9.

Пример — Grafana: порт 3000, данные в /var/lib/grafana, пароль админа в переменной GF_SECURITY_ADMIN_PASSWORD.

docker run -d --name grafana -p 3000:3000 -v grafana-data:/var/lib/grafana -e GF_SECURITY_ADMIN_PASSWORD=MyPass123 --restart unless-stopped grafana/grafana
# открыть http://сервер:3000, логин admin (без переменной пароль тоже admin)
# без тега скачается последняя версия; для прода укажи версию из вкладки Tags

Порты, папки и переменные популярных образов:

образ              порт   папка данных               переменные
postgres:16        5432   /var/lib/postgresql/data   POSTGRES_PASSWORD (обязательна)
mysql:8.4          3306   /var/lib/mysql             MYSQL_ROOT_PASSWORD (обязательна)
redis:7            6379   /data                      -
mongo:7            27017  /data/db                   -
nginx              80     /usr/share/nginx/html      -
grafana/grafana    3000   /var/lib/grafana           GF_SECURITY_ADMIN_PASSWORD
nextcloud          80     /var/www/html              -

8. Свой образ: Dockerfile

Нужен, чтобы упаковать свою программу: собрал образ один раз — и он запускается одной командой на любом компьютере с Docker. Пример — маленький веб-сервер на Python. Сам Python ставить не надо: он будет внутри образа. Создай папку hello и в ней три файла.

app.py — сама программа:

from flask import Flask
app = Flask(__name__)

@app.route("/")
def index():
    return "Привет из контейнера!"

app.run(host="0.0.0.0", port=8000)

requirements.txt — какие библиотеки нужны:

flask

Dockerfile — рецепт сборки образа:

FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install -r requirements.txt
COPY . .
CMD ["python", "app.py"]

Что делает каждая строка:

FROM python:3.12-slim       взять за основу готовый образ, где уже есть Python
WORKDIR /app                дальше всё делать в папке /app внутри образа
COPY requirements.txt .     скопировать туда список библиотек
RUN pip install ...         выполнить команду при сборке: поставить библиотеки
COPY . .                    скопировать весь проект
CMD ["python", "app.py"]    что запускать, когда стартует контейнер

Собрать и запустить (команды — из папки hello):

docker build -t hello:1.0 .                         # собрать образ hello версии 1.0; точка = эта папка
docker run -d --name hello -p 8000:8000 hello:1.0   # открой http://localhost:8000
  • Поменял код — собери новую версию (docker build -t hello:1.1 .), удали старый контейнер и запусти новый.
  • RUN выполняется один раз при сборке, CMD — при каждом запуске контейнера.
  • Библиотеки ставятся до копирования кода специально: Docker запоминает готовые шаги, и после правки кода пересборка занимает секунды.
  • Программа должна слушать 0.0.0.0, а не 127.0.0.1 — иначе снаружи контейнера её не видно.
  • Файл .dockerignore (как .gitignore) — что не копировать в образ: .git, .venv, файлы с паролями.

Чужой проект с GitHub, в котором уже есть Dockerfile, собирается так же:

git clone https://github.com/автор/проект.git
cd проект
docker build -t проект .

Перенести образ на сервер — через Docker Hub (бесплатный аккаунт на hub.docker.com):

docker login                           # войти в аккаунт
docker tag hello:1.0 ЛОГИН/hello:1.0   # имя для Docker Hub: логин/образ:версия
docker push ЛОГИН/hello:1.0            # загрузить
# на сервере: docker run -d -p 8000:8000 ЛОГИН/hello:1.0

9. Docker Compose: всё одной командой

Длинные docker run неудобно помнить и повторять. Compose — те же настройки, только записанные в файл compose.yaml. Сервисы из одного файла сами видят друг друга по имени.

docker run                     compose.yaml
--name db                      services: -> db:
-p 8080:80                     ports: - "8080:80"
-v db-data:/var/lib/mysql      volumes: - db-data:/var/lib/mysql
-e KEY=value                   environment: KEY: value
--restart unless-stopped       restart: unless-stopped
--network ...                  не нужно: общая сеть создаётся сама

Пример: сайт на WordPress с базой MySQL. Создай папку blog, в ней файл compose.yaml:

services:
  db:
    image: mysql:8.4
    environment:
      MYSQL_ROOT_PASSWORD: ${DB_ROOT_PASS}
      MYSQL_DATABASE: wordpress
      MYSQL_USER: wp
      MYSQL_PASSWORD: ${DB_PASS}
    volumes:
      - db-data:/var/lib/mysql
    restart: unless-stopped

  wordpress:
    image: wordpress:6
    ports:
      - "8080:80"
    environment:
      WORDPRESS_DB_HOST: db
      WORDPRESS_DB_USER: wp
      WORDPRESS_DB_PASSWORD: ${DB_PASS}
      WORDPRESS_DB_NAME: wordpress
    volumes:
      - wp-data:/var/www/html
    depends_on:
      - db
    restart: unless-stopped

volumes:
  db-data:
  wp-data:

Рядом файл .env с паролями (придумай свои, в git его не клади):

DB_ROOT_PASS=RootPass123
DB_PASS=WpPass123

docker compose up -d       # поднять всё (команды — из папки blog)
docker compose ps          # что запущено
docker compose logs -f     # логи всех сервисов (выход: Ctrl+C)
docker compose down        # удалить контейнеры (данные в томах живы)
docker compose down -v     # ⚠ то же + удалить тома = сайт и база пропадут

Открой http://localhost:8080 — там установщик WordPress. Пишет «Error establishing a database connection» — подожди полминуты, база ещё стартует.

  • WORDPRESS_DB_HOST: db — WordPress находит базу просто по имени сервиса.
  • ${DB_PASS} подставляется из файла .env.
  • Отступы в YAML — только пробелами, табы ломают файл.
  • Поменял compose.yaml — снова docker compose up -d: пересоздастся только изменённое.
  • Обновить всё: docker compose pull, затем docker compose up -d.
  • docker-compose через дефис — старая версия, сейчас пишут docker compose. Строка version: в начале файла больше не нужна.

10. Уборка места

Docker со временем копит старые образы и остановленные контейнеры, и диск заканчивается. Раз в месяц:

docker system df           # сколько места занято
docker system prune -a     # удалить всё неиспользуемое: остановленные контейнеры, лишние образы, кеш сборки

Тома с данными эта команда не трогает. Неиспользуемые тома удаляет docker volume prune -a — ⚠ это данные, только если точно не нужны.

11. Если что-то не работает

Первым делом всегда:

docker ps -a       # контейнер работает (Up) или упал (Exited)?
docker logs имя    # причина почти всегда в последних строках лога
  • Exited (0) сразу после запуска — не ошибка: программа внутри просто закончила работу. Контейнер живёт, пока работает его главная программа.
  • Exited (1) или Restarting — программа падает, читай docker logs. Частые причины: не задан обязательный пароль (-e), ошибка в конфиге, нет прав на папку.
  • Exited (137) — не хватило памяти или контейнер убили принудительно. Проверь docker stats.
  • port is already allocated — порт на сервере уже занят другим контейнером или программой. Возьми другой слева: -p 8081:80.
  • container name "/kuma" is already in use — контейнер с таким именем уже есть: docker rm -f kuma или выбери другое имя.
  • Страница не открывается → контейнер в статусе Up? В колонке PORTS есть твой порт? Открываешь левый порт из -p? Firewall сервера или облака пропускает этот порт?
  • Контейнер не видит другой → обращайся по имени контейнера или сервиса, а не через localhost; оба должны быть в одной сети (в Compose — всегда).
  • Нет интернета внутри → docker run --rm alpine ping -c 2 8.8.8.8. IP пингуется, а сайты по имени нет — проблема DNS: добавь --dns 8.8.8.8. Не пингуется ничего после правки firewall — sudo systemctl restart docker.
  • Не скачиваются образы (timeout, 403, 429 toomanyrequests) → Docker Hub недоступен или упёрся в лимит: docker login или зеркало в daemon.json: "registry-mirrors": ["https://mirror.gcr.io"].
  • permission denied … docker.sock → пользователь не в группе docker: см. установку, перелогинься.
  • No space left on device → уборка.
  • После установки Docker пропал доступ к части локальной сети → Docker занял подсеть 172.17–172.31.x.x или 192.168.x.x, которая совпала с вашей. Задай свои подсети в daemon.json и перезапусти Docker: 
    {
  "bip": "10.200.0.1/24",
  "default-address-pools": [{"base": "10.201.0.0/16", "size": 24}]
}
  • Через VPN из контейнера «виснет» HTTPS → уменьши MTU сети: docker network create -o com.docker.network.driver.mtu=1400 mynet.

daemon.json — файл настроек Docker: на Linux /etc/docker/daemon.json (все настройки — в одном JSON), в Docker Desktop — Settings → Docker Engine. После правки: sudo systemctl restart docker.

Сетевые проблемы удобно смотреть изнутри: docker run --rm -it --network container:web nicolaka/netshoot — набор утилит (ping, curl, dig, tcpdump) прямо в сети контейнера web.

12. Безопасность: 5 правил

  1. Не открывай лишнего наружу. Базы (5432, 3306, 6379, 27017) в интернет не публикуй — боты находят открытые базы очень быстро. Нужно только самому серверу — -p 127.0.0.1:5432:5432; нужно другим контейнерам — вообще без -p, через общую сеть.
  2. Пароли — в файле .env, а не в командах, Dockerfile или git. Всё, что попало в образ, из него можно достать.
  3. Образы — официальные или от автора программы, с версией в теге: postgres:16, а не просто postgres.
  4. Группа docker = права root. Не давай её кому попало; не пробрасывай в контейнеры /var/run/docker.sock и не запускай с --privileged, если не понимаешь зачем.
  5. Обновляйся: docker compose pull, затем docker compose up -d.

13. Практика

Сделай по порядку: сначала сам, потом сверься с решением.

1. Запусти nginx на порту 8081, открой страницу в браузере, посмотри лог, удали контейнер.

Решение
docker run -d --name t1 -p 8081:80 nginx
# открыть http://localhost:8081
docker logs t1
docker rm -f t1

2. Создай папку site с файлом index.html (текст: Hello Docker) и покажи её через nginx на порту 8082. Поменяй текст в файле и обнови страницу, контейнер не трогай.

Решение
docker run -d --name t2 -p 8082:80 -v ./site:/usr/share/nginx/html:ro nginx

3. Запусти PostgreSQL с томом, создай таблицу, удали контейнер, запусти новый с тем же томом — таблица должна остаться.

Решение
docker run -d --name pg -e POSTGRES_PASSWORD=pass -v pgdata:/var/lib/postgresql/data postgres:16
# подожди ~5 секунд, пока база стартует
docker exec pg psql -U postgres -c "create table t(x int); insert into t values (42);"
docker rm -f pg
docker run -d --name pg -e POSTGRES_PASSWORD=pass -v pgdata:/var/lib/postgresql/data postgres:16
docker exec pg psql -U postgres -c "select * from t;"   # 42 на месте

4. Создай сеть lab, запусти в ней nginx с именем lab-web и открой его страницу по имени из другого контейнера.

Решение
docker network create lab
docker run -d --name lab-web --network lab nginx

Самопроверка

Чем образ отличается от контейнера?Образ — как установщик, контейнер — запущенная из него программа. Из одного образа можно запустить сколько угодно контейнеров.
Пересоздал контейнер с базой — данные пропали. Почему?Данные писались внутрь контейнера. Папку данных надо держать в томе: -v pgdata:/var/lib/postgresql/data.
В -p 8080:80 какой порт чей?Слева сервер, справа контейнер. В браузере открываешь 8080.
Контейнер сразу завершился с Exited (0). Это ошибка?Нет: программа внутри просто закончила работу. Контейнер живёт, пока работает его главная программа.
Контейнеры не находят друг друга по имени. Почему?Они не в одной своей сети. Создай сеть (docker network create) или используй Compose.
Чем RUN отличается от CMD?RUN выполняется один раз при сборке образа, CMD — при каждом запуске контейнера.
Зачем Compose, если есть docker run?Все настройки в одном файле: не надо помнить длинные команды, весь набор сервисов поднимается и обновляется одной командой.
ufw закрыт, а порт контейнера доступен из сети. Почему?Docker сам прописывает правила firewall для -p, и трафик идёт мимо правил ufw. Публикуй на 127.0.0.1 или не публикуй порт вовсе.
Как обновить сервис на новую версию?docker compose pull, затем docker compose up -d. Данные в томах сохранятся.

Дальше, когда понадобится: multi-stage сборка (маленькие образы), healthcheck (Docker сам проверяет, жив ли сервис), Kubernetes (когда серверов много).
